# 扫描结果表紧凑化设计

## 目标

扫描结果表优先帮助用户在一屏内确认“是什么、属于谁、在哪里、有什么影响、会怎么处理”。长证据、注册表位置和完整操作说明继续由右侧详情与悬停提示承载。

## 采用方案

结果表固定为八个视觉单元：勾选框、软件图标、风险、项目、软件、位置、影响、处理。六个文字表头均使用不换行短标题：`风险`、`项目`、`软件`、`位置`、`影响`、`处理`。

- `项目`：去掉“普通文件右键：会出现”“资源管理器：疑似会出现”等重复场景前缀，保留真正可辨认的菜单、服务或组件名称。
- `软件`：显示现有已确认厂商，不用图标反推厂商。
- `位置`：把分类压缩为“文件右键”“后台服务”“计划任务”“文件关联”等短词。
- `影响`：只显示“增加右键入口”“后台常驻”“随开机启动”等一句摘要。
- `处理`：只显示“备份后删除”“备份后禁用”“打开卸载器”或“仅提示”。

完整的原始名称、影响说明、处理动作、技术位置和证据不删除，继续显示在右侧详情和整行悬停提示中。

## 布局

- 勾选、图标、风险和处理使用固定窄列。
- 项目、软件、位置和影响按比例填满剩余宽度。
- 表头禁止换行，行内容保持单行省略号。
- 不增加横向滚动，不缩小现有字体。

## 验收

1. 默认窗口和最小窗口下六个文字表头完整显示。
2. 右键菜单项目不再以“普通文件右键：疑似会出现……”开头。
3. 表格内处理文案不再显示“备份后删除这条注册表项”等长句。
4. 悬停提示和右侧详情仍保留完整原文。
5. UI 回归无越界、等待光标和 DataGridView 数据错误。
