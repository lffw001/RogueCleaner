# 右键菜单发现与风险展示规范

## 两个界面的职责

- “右键管理”显示完整的第三方右键库存，包括正常的 Beyond Compare、WinRAR、Notepad++ 等菜单，供用户显示、隐藏和检查来源。
- “开始扫描”显示需要提示或处理的风险结果。正常且组件完整的第三方菜单不进入风险列表，避免把正常软件重新误报成流氓项。

## 覆盖一致性

1. 两条链必须覆盖传统 `shell` 命令、`ContextMenuHandlers`、拖放处理器、文件/文件夹/磁盘/桌面场景，以及 Windows 11 应用包的现代和传统兼容声明。
2. 应用包风险扫描不得加载第三方动态标题 DLL；只读取清单、组件路径、发布者和现有身份/行为规则，避免拖慢主扫描。
3. 已禁用项目、正常项目、异常项目可以有不同展示结果，但不能因为注册形式不同而完全跳过风险分类。

## 风险分层

- 正常、文件存在、无异常行为：仅在右键管理显示。
- 文件缺失、注册残留、身份不足：开始扫描中“仅提示”，不能一键清理。
- 快速扫描未解析到组件路径时只能视为“未知”，不得据此判定文件缺失；只有路径已明确且文件确实不存在时才提示残留。
- 身份确认且命中已知异常组件或弹窗/守护行为：进入开始扫描，并提供可恢复的禁用动作。
- 仅凭厂商名称、安装了右键菜单或属于国内软件，不能判定为风险。

## 回归要求

- 扫描根目录清单必须覆盖右键管理中的标准注册形式。
- Windows 11 应用包解析必须同时覆盖现代和传统兼容声明。
- 正常 Beyond Compare/WinRAR 类项目不得进入风险扫描结果。
- 构造的缺失组件或明确异常组件必须进入“仅提示”或可恢复处理结果。
