# 全项目软件图标显示规范

本规范适用于总览、启动项管理、右键管理、弹窗/流氓诊断、恢复中心以及后续新增的所有列表和详情页。

## 强制规则

1. 已确认所属软件的项目必须优先显示该软件主程序图标，不能长期显示流氓软件克星占位图标、Windows 通用文件图标或 Shell DLL 通用图标。
2. 图标来源优先级固定为：
   - 软件明确声明且指向主程序/独立图标资源的图标；
   - 已安装程序 `DisplayIcon`；
   - 已安装程序目录中与产品名匹配的主 EXE；
   - 实际执行命令的 EXE；
   - 同一软件目录中的代表性 EXE；
   - Shell DLL/服务 DLL 自带图标；
   - 全项目统一占位图标。
3. 动态右键标题探测返回的 DLL 路径只是组件证据，不能自动标记为“显式软件图标”。
4. 软件归属必须由发布者、产品名、文件版本、安装项或签名等证据确认；不能仅凭路径中的关键词猜图标。
5. 每个展示对象必须保留 `IconSource`，详情中能够说明图标来自主程序、安装项、命令文件还是兜底组件。

## 性能与安全

- 已安装程序匹配结果必须缓存，禁止每个表格单元重复遍历卸载项。
- 图标解析在后台身份识别队列完成，不阻塞 UI 线程。
- 只读取文件版本、注册表卸载项和图标资源，不启动关联软件。
- 无法可靠匹配时使用统一占位图标，禁止用错误软件图标冒充。

## 回归门槛

1. 通用回归必须覆盖“显式 DLL 图标仍应回退到同软件主程序”的情况。
2. 已确认软件必须得到非空、存在且可读的 `IconSource`。
3. WindowsApps 外壳组件存在对应桌面主程序时，必须通过发布者和产品名关联到主程序图标。
4. UI 冒烟截图必须抽查第三方右键、服务、启动项和诊断结果的图标，不能只验证文字与布局。
5. 新增模块如果绕过 `SoftwarePresentationResolver`，视为不符合项目规范。
