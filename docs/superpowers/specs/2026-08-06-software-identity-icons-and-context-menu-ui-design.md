# 全项目软件身份图标与右键管理小白化设计

## 1. 目标

本轮同时解决三个一致性问题：

1. 主程序和全部子窗体标题栏统一使用 `src/app.ico`，不再出现 WinForms 默认图标。
2. 所有代表软件、服务或组件的列表项均显示可追溯的软件名称与真实图标，帮助用户快速区分来源。
3. 右键管理采用已确认的“场景导航版”，主界面只呈现普通用户能理解的名称、出现位置、关联软件和操作影响，技术字段折叠到详情区。

身份与图标用于帮助理解，不能替代风险判定。找不到可靠证据时必须显示“来源未确认”和统一未知图标，禁止根据模糊关键词猜厂商。

## 2. 范围

### 2.1 统一窗体图标

以下窗体全部通过同一个入口设置主程序图标：

- 主窗体
- 恢复中心
- 反馈窗体
- 右键菜单管理
- 右键菜单添加/编辑
- 专用菜单管理及添加窗体
- 高级右键兼容及 IE 菜单编辑窗体
- 关于/开源致谢窗体

统一入口负责从当前 EXE 提取图标；提取失败时使用内置资源或安全回退，不允许各窗体自行重复实现。

### 2.2 显示软件图标的项目

- 主扫描结果：启动项、服务、计划任务、右键扩展、浏览器宿主、文件关联、卸载残留和运行中组件。
- 右键菜单管理：Shell 命令、Shell 扩展、文件类型菜单和命令仓库。
- 专用模块：ShellNew、SendTo、OpenWith 和 GUID 屏蔽。
- 高级模块：WinX、现代/UWP、IE 旧式菜单和安全增强菜单。
- 恢复中心：根据恢复结果中的目标、厂商和技术位置显示对应软件图标；无法归属时显示操作类型图标。

反馈窗体、编辑窗体等没有软件列表的页面只统一标题栏 ICO，不额外添加无意义的项目图标。

## 3. 集中式身份与图标解析器

新增独立的 `SoftwarePresentationResolver`，输入统一证据对象，输出：

- `DisplayVendor`：用户可读的软件/系统来源。
- `IconImage`：列表使用的 20×20 或 24×24 图像。
- `IconSource`：图标来源路径，供技术详情和回归测试使用。
- `Confidence`：Confirmed、System、Unknown。
- `Explanation`：为什么归属到该软件。

### 3.1 证据优先级

1. 注册表明确声明且指向存在文件的 `Icon` / `DisplayIcon`。
2. 项目执行命令中的 EXE 路径。
3. 服务 `PathName`；若为 `svchost.exe`，只确认 Windows 系统组件，不冒充具体第三方软件。
4. 计划任务动作中的执行文件。
5. CLSID 的 `LocalServer32` 或 `InprocServer32` 文件。
6. SendTo/WinX 快捷方式目标文件。
7. UWP/Appx 清单和已安装包图标。
8. 已确认厂商的同安装目录主程序图标。
9. Windows 系统图标或统一“来源未确认”图标。

解析器会清理引号、环境变量、参数、资源索引（如 `app.exe,0`）和系统宿主包装，但不会执行目标文件、加载第三方程序集或联网下载图标。

### 3.2 身份和图标分离

- 厂商身份继续使用现有 Publisher、产品名、有效签名、文件版本、安装目录和人工可见文本证据。
- 图标只负责视觉展示，不增加风险分数，不单独确认厂商。
- 已确认厂商但没有专属图标时，可以复用同一安装目录中已确认主程序的图标。
- 图标与身份冲突时，以身份证据为准；详情中记录图标来源，不改变厂商结论。

### 3.3 性能与缓存

- 扫描和枚举先返回文本结果，图标在后台分批解析。
- UI 初始显示轻量占位图标，解析完成后只更新对应行，不重绑整张表。
- 缓存键由规范化文件路径、资源索引和文件最后修改时间组成。
- 同一路径只提取一次；克隆图像交给 UI 使用，缓存对象集中释放。
- 失败结果短期缓存，避免 1600 项列表重复访问同一个无效路径。
- 图标解析不得设置全窗体等待光标，不得阻塞鼠标移动、搜索或列表滚动。

## 4. 右键管理场景导航版

### 4.1 页面层级

标题：`管理鼠标右键里的菜单`

说明：`控制右键点击文件、文件夹或桌面空白处时，哪些菜单需要显示。`

一级场景导航：

- 文件右键
- 文件夹右键
- 桌面空白处
- 新建菜单
- 发送到
- 打开方式
- 系统高级

原“专用模块”和“高级兼容”不再作为含义不明的大按钮；它们的功能被映射到上述场景。高级模块仍保留完整能力，只改变入口和说明。

### 4.2 独立紧凑工具栏

筛选/搜索单独一行，工具栏再单独一行。工具栏高度约 30 像素，按钮使用小尺寸：

- 刷新
- 显示选中项
- 隐藏选中项
- 修改名称
- 添加菜单
- 删除
- 复制信息
- 更多工具

按钮按当前项目能力动态启用。危险操作保留二次确认和恢复说明；删除不伪装成普通操作。

### 4.3 小白列表字段

主列表只显示：

1. 软件图标
2. 当前状态：正在显示 / 已隐藏 / 只读
3. 右键里显示的名称
4. 什么时候会出现
5. 关联软件
6. 操作建议：常用、按需保留、可保持隐藏、来源未确认

`Shell 命令`、`CLSID`、注册表 32/64 位、HKCU/HKLM、命令行和子菜单引用不再作为主列表列。

### 4.4 详情面板

详情面板先回答四个普通问题：

- 这是什么？
- 它会在哪里出现？
- 显示/隐藏后有什么影响？
- 它属于哪个软件，依据是什么？

底部提供折叠的“查看技术信息”，其中显示命令、图标来源、CLSID、注册表位置、用户范围和 32/64 位视图。

技术位置仍可复制和定位注册表，但移入“更多工具”，避免普通用户误触。

## 5. 场景和人话映射

内部技术类型通过集中映射转换：

- `Software\Classes\*`：右键点击任意文件时
- 文件扩展名根：右键点击对应类型文件时
- `Directory\shell`：右键点击文件夹时
- `Directory\Background`：右键点击文件夹空白处时
- `DesktopBackground`：右键点击桌面空白处时
- `Drive`：右键点击磁盘时
- ShellNew：打开“新建”菜单时
- SendTo：打开“发送到”菜单时
- OpenWith：选择“打开方式”时
- WinX：右键点击开始按钮时
- UWP/现代菜单：Windows 11 右键菜单中

无法可靠转换的项显示“系统扩展位置”，并在详情提供原始位置。

## 6. 错误处理与安全边界

- 文件不存在、无权限、图标损坏或资源索引无效时使用回退图标，不中断扫描。
- 单个图标解析异常只记调试日志，不弹窗轰炸用户。
- 受保护注册表继续采用当前“记录警告并跳过”策略。
- 不获取 TrustedInstaller 权限，不接管 ACL，不绕过软件自保护。
- 不把图标相似、文件名相似或路径关键词当成厂商确认依据。
- 未确认来源的项目不因新增图标能力进入一键清理链。

## 7. 验收标准

1. 枚举全部 Form 类型，标题栏图标均与主程序一致。
2. 主扫描、右键基础/专用/高级和恢复中心列表均存在图标列。
3. 使用测试 EXE、服务路径、任务动作、CLSID DLL、快捷方式和未知路径验证解析优先级。
4. 同一文件路径的图标只提取一次，重复 1000 行不线性重复 IO。
5. 1600 项右键菜单枚举时鼠标保持正常，搜索和滚动可用，图标可稍后逐批出现。
6. `svchost.exe` 显示 Windows 系统组件，不错误套用第三方厂商。
7. 无图标/无身份项目显示统一未知图标和“来源未确认”。
8. 右键管理主列表不出现 Shell、CLSID、HKLM、Registry32 等必须由小白理解的技术列。
9. 显示、隐藏、编辑、添加、删除、恢复和定位注册表原功能全部保留并通过回归。
10. 默认窗口、最小窗口和 125%/150%/200% DPI 下工具栏不遮挡、不换行失控，详情区保持可读。

## 8. 非目标

- 不建立在线图标库或云端厂商数据库。
- 不用图标参与恶意判定。
- 不删除现有高级功能，只调整入口和解释方式。
- 不在本轮发布新版本；是否提交、推送和创建 Release 仍遵守项目交付规则。
# 项目级约束补充

图标识别与显示必须遵守 `docs/development/software-icon-presentation-standard.md`。动态菜单 DLL 只作为组件证据，不能阻止解析器继续寻找已安装软件的主程序图标；新增模块必须接入统一 `SoftwarePresentationResolver`。
