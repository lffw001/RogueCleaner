# ContextMenuManager 功能融合与注册表权限容错设计

## 1. 决策摘要

本项目将完整吸收 ContextMenuManager 的用户可见右键菜单管理能力，但不复制其 GPLv3 源码、图片、字典或内部控件框架。所有功能依据 Windows 注册表、文件系统和 Shell 行为独立实现，继续使用本项目 MIT 许可证、单文件 EXE、备份恢复和低误伤原则。

上游项目：

- 名称：ContextMenuManager
- 作者：蓝点lilac
- 地址：https://github.com/BluePointLilac/ContextMenuManager
- 许可证：GNU GPL v3
- 本项目关系：功能设计与覆盖范围参考；不直接复制或链接 GPL 代码

本次工作同时修复 v2.0.12 外部用户反馈的注册表只读访问异常：任何单个受保护注册表项都不能再终止整次扫描。

## 2. 目标与非目标

### 2.1 目标

1. 右键管理从“只列出疑似流氓项”升级为“列出并管理全部右键入口”。
2. 保留独立的流氓诊断视角，正常右键项不得因为进入管理列表而被标记为风险。
3. 覆盖 ContextMenuManager 的主要用户能力：查看、启停、编辑、添加、删除、定位、子菜单、文件类型、ShellNew、发送到、打开方式、ShellEx、UWP、WinX、IE 旧菜单、增强菜单和 GUID 屏蔽。
4. 所有变更先备份、可恢复、可复核；失败不能破坏原项目。
5. 普通用户遇到无权读取的注册表项时继续完成其余扫描，并得到明确的“不完整扫描”提示。
6. 在软件和 README 中加入对蓝点lilac / ContextMenuManager 的公开致谢。

### 2.2 不纳入的上游基础设施

以下内容不是右键管理业务能力，继续使用本项目已有实现，不重复移植：

- 上游更新器、下载器和版本配置
- 上游捐赠页面
- 上游 WinForms 控件库、主题、图标和截图资源
- 上游多语言加载框架及翻译维护工具
- 上游配置目录和窗口状态保存方式
- 上游 TrustedInstaller 所有权接管实现

不纳入基础设施不等于缩减右键功能。对应业务能力仍由本项目独立实现。

## 4. 功能对照与取舍

| 上游能力 | 当前项目现状 | 融合决策 |
|---|---|---|
| 文件、文件夹、目录背景、桌面背景、磁盘、所有对象右键 | 已扫描部分 Shell/ShellEx 路径，只显示命中规则的项目 | 保留现有识别逻辑，新增完整清单与管理动作 |
| 此电脑、回收站、库右键 | 已扫描部分资源管理器入口 | 扩充为独立场景，管理列表显示全部项目 |
| `.lnk`、`.exe`、未知类型、自定义扩展名 | 只扫描固定文件扩展名关联 | 改为动态枚举扩展名、ProgID、PerceivedType 和 SystemFileAssociations |
| UWP / 现代菜单 | 未形成独立管理模块 | 独立枚举和启停，保留未知结构只读提示 |
| ShellNew 新建菜单 | 仅做部分文件关联诊断 | 支持查看、排序、启停、添加模板、编辑和恢复 |
| 发送到 | 只覆盖启动文件夹，不覆盖 SendTo | 支持当前用户和默认用户模板的查看、启停、添加、删除与恢复 |
| 打开方式 | 只报告默认打开程序 | 支持 OpenWithList、OpenWithProgids、Applications 和命令定位 |
| WinX | 未覆盖 | 支持分组、排序、启停、添加快捷方式和恢复；哈希独立实现并用真实系统验收 |
| 拖放处理器 | 右键根路径中有部分 ShellEx | 新增 DragDropHandlers 专门视图与启停 |
| 公共命令仓库 / 子菜单 | 只解析部分命令文本 | 支持 CommandStore、SubCommands、级联子菜单的查看、编辑和引用关系 |
| 自定义注册表路径分析 | 无直接入口 | 增加只读分析入口；写入动作仍受允许路径和备份约束 |
| 增强菜单 | 无 | 独立编写安全配方，不复制上游 XML 字典 |
| 详细编辑 | 右侧详情只读 | 增加受控字段编辑和高级键值编辑；默认只读、提交前显示差异 |
| GUID 屏蔽 | 未作为独立管理页 | 支持 HKCU/HKLM Shell Extensions `Blocked` 查看、添加、移除和恢复 |
| IE 旧右键菜单 | 未覆盖 | 保留兼容模块；系统无 IE 结构时显示为空，不创建无意义键 |
| 导航注册表、文件位置 | 详情中显示路径但无统一动作 | 增加“定位注册表”“打开文件位置”“复制技术信息” |
| 修改名称、图标、命令 | 无通用编辑器 | 在安全字段模型中实现，写入前备份并校验命令路径 |
| 永久删除 | 诊断清理支持部分删除 | 统一进入现有清理引擎，二次确认、备份、复核、可恢复 |

## 5. 产品结构

### 5.1 两种视角分离

`右键管理` 与 `弹窗 / 流氓诊断` 使用同一底层枚举数据，但目的不同：

- 右键管理：显示全部已发现项目，默认不评价好坏，允许用户主动管理。
- 流氓诊断：只显示有身份、行为和风险证据的可疑项目，继续使用现有误报控制。

任何普通右键项不得因为出现在管理清单中自动获得风险分数，也不得进入“一键清理”。

### 5.2 右键管理页

左侧保留现有一级导航；进入“右键管理”后，在内容区增加二级分类：

1. 常用位置
2. 文件类型
3. Shell 扩展
4. 新建菜单
5. 发送到
6. 打开方式
7. 子菜单 / 命令仓库
8. WinX / UWP / IE
9. GUID 屏蔽

中央列表显示：状态、名称、类型、作用位置、厂商/文件、来源范围、权限状态。右侧详情显示完整路径、命令、图标、CLSID、签名/版本信息、启停方式和最近备份。

操作栏按项目能力动态显示：启用、禁用、编辑、添加、删除、恢复、定位注册表、打开文件位置、复制详情、刷新资源管理器。

### 5.3 关于与致谢

顶部增加轻量的“关于”入口，打开统一窗体：

- 当前软件作者和主页
- MIT 许可证
- ContextMenuManager 参考说明、蓝点lilac 和项目链接
- 其它后续开源依赖/参考项目

作者署名仍保持不可点击；两个主页图标保持独立跳转。

## 6. 技术架构

### 6.1 数据模型

新增 `ContextMenuEntry`，与诊断用 `Finding` 分离。核心字段：

- 唯一键、场景、显示名、状态
- 注册表 Hive/View/SubKey/ValueName
- 文件路径、命令、参数、图标、CLSID/ProgID
- 来源范围：当前用户、所有用户、32 位、64 位、文件系统
- 支持动作集合
- 是否需要管理员权限、是否只读、权限失败原因
- 厂商身份与签名证据（可为空）
- 关联的备份批次

诊断桥接器只把符合现有风险条件的 `ContextMenuEntry` 转换成 `Finding`。

### 6.2 枚举层

新增独立枚举器，每个枚举器只负责一种 Windows 结构：

- `ShellCommandEnumerator`
- `ShellExtensionEnumerator`
- `FileAssociationEnumerator`
- `ShellNewEnumerator`
- `SendToEnumerator`
- `OpenWithEnumerator`
- `CommandStoreEnumerator`
- `WinXEnumerator`
- `LegacyIeMenuEnumerator`
- `GuidBlockedEnumerator`

枚举层只读，不取得所有权、不修改 ACL、不创建缺失项。HKCU/HKLM、32/64 位视图和 HKCR 合并结果需要保留真实来源，不能只显示合并后的虚拟路径。

### 6.3 修改层

所有启停、编辑、添加、删除操作统一进入 `ContextMenuMutationService`：

1. 解析并限制目标范围。
2. 读取当前状态，生成可读差异。
3. 写入操作前备份注册表或文件。
4. 执行单个原子动作。
5. 重新读取并验证目标状态。
6. 写入现有恢复中心可识别的结果记录。
7. 失败时回滚本次已完成步骤，并保留错误证据。

启停优先使用 Windows 已有机制：

- Shell 命令：`LegacyDisable`、`ProgrammaticAccessOnly` 或场景允许的显隐值
- ShellEx：HKCU/HKLM `Shell Extensions\Blocked`
- 文件项目：移动到数据目录中的禁用区并保存原路径
- 其它结构：按类型保存原值后做最小可逆修改

不通过改注册表所有者或写入永久 ACL 获得权限。受保护写入失败时提示管理员重启；管理员仍无权时保持只读并报告具体路径。

### 6.4 备份与恢复

复用现有恢复中心，不再建立第二套备份格式。每个右键管理动作生成独立操作记录，至少包含：

- 原注册表导出或原值/类型
- 原文件及路径
- 修改前后摘要
- Hive/View 与重定向信息
- 验证结果

恢复同样执行后置复核。恢复失败不能删除备份。

## 7. v2.0.12 权限异常修复

### 7.1 根因

`RegistryHelper.OpenSubKey()` 在打开受保护子键时抛出 `SecurityException`。`SafeSubKeyNames()` 和 `ReadString()` 只能保护已成功打开的句柄，异常最终逃出 `ScanExplorerNamespaces()`，再被 `Parallel.Invoke()` 包装成 `AggregateException`，导致整次扫描失败。

### 7.2 修复行为

1. 增加扫描专用的安全只读打开方法，只捕获 `SecurityException` 和 `UnauthorizedAccessException`。
2. 每个被拒绝目标记录结构化 `ScanWarning`：阶段、Hive/View、脱敏路径、异常类型。
3. 当前注册表分支跳过，其他分支和扫描器继续运行。
4. 并行扫描器增加预期权限异常隔离，防止遗漏的只读入口再次拖垮全部扫描。
5. 非权限类异常仍按错误处理，不能用大范围 `catch {}` 掩盖程序缺陷。
6. 扫描结束状态显示：`扫描完成，发现 N 项；另有 M 个受保护位置无法读取。`
7. 证据报告包含警告摘要，不把无法读取误报为“项目不存在”或“已清理”。
8. `OpenBaseKey` 句柄在返回子键前正确释放，避免长期扫描累计注册表句柄。

### 7.3 管理员行为

- 普通用户：扫描可完成；需要管理 HKLM/服务等项目时提供管理员重启。
- 管理员：正常读取可访问项目；仍受 ACL 保护的项目只提示，不接管所有权。
- 权限不足不自动生成可清理项，也不能用于判断厂商或风险。

## 9. 测试策略

1. 新增验证版权限注入测试：指定注册表路径模拟抛出 `SecurityException`，确认扫描仍完成、警告数正确、其他扫描器有结果。
2. 所有写入测试只使用 `CodexRogueCleanerTest` 前缀的 HKCU 项和隔离测试目录。
3. 为每种动作执行“创建 → 枚举 → 备份 → 修改 → 复核 → 恢复 → 复核”。
4. HKLM、WinX 和资源管理器刷新只在独立验收模式下测试，并在测试后清理模拟工件。
5. 身份误报、反馈脱敏、扫描性能、UI 布局和现有清理恢复烟测必须全部继续通过。
6. 增加静态许可证检查：发布包和源码不得包含上游源文件、资源文件或命名空间。
7. 最终人工验证外部用户报告中的异常路径：受限项产生警告而不是 `AggregateException`。

## 10. 验收标准

1. 单个或多个注册表路径拒绝访问时，扫描仍正常结束。
2. 管理页能显示正常和可疑右键项，诊断页只显示有证据的风险项。
3. 所有上游用户可见右键管理类别均有对应入口和操作能力。
4. 每个修改动作都有备份、复核和恢复证据。
5. 不修改注册表 ACL，不取得 TrustedInstaller 所有权。
6. 不复制或嵌入 ContextMenuManager GPL 源码、字典和图片。
7. 关于窗体和 README 正确显示蓝点lilac、项目链接和参考关系。
8. 正式发布仍为单文件 EXE，现有扫描、启动项管理和流氓诊断不回退。
