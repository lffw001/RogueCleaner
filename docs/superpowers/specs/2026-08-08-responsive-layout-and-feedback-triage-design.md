# 全局响应式界面与反馈闭环设计

## 目标

让主窗口及各模块在 Windows 100%、125%、150% 和 200% 缩放下保持可操作；将 GitHub Issues 作为每次改动前后的回归清单。

## 设计

- 保留桌面端信息密度，不降低字体或裁切文字来换取空间。
- 顶部标题和工具栏保持单行控件尺寸；可用宽度不足时使用横向滚动而非压缩。
- 总览统计卡根据实际可用宽度在四列与两列两行之间切换，卡片高度随布局同步调整。
- 主内容区保持结果表优先：右侧详情栏限制为可读的最小宽度，狭窄窗口下表格使用自身水平滚动条，不挤压列至无法阅读。
- 页脚和次级窗体移除对大块绝对宽度的依赖，允许文本省略但不得遮挡关键操作。

## 反馈闭环

每次修复前读取仓库全部开放和最近关闭的 Issues，并把每项标为：已覆盖、待修复、需要样本或不纳入当前架构。所有“已覆盖”必须有代码或回归证据；其余项必须给出下一步处理方式。Issue 的公开状态和评论只在用户明确授权时修改。

## 验收

通过 `--ui-smoke` 获取默认窗口、最小窗口和反馈窗体截图；在可用的 Windows 桌面环境中额外验证 100%、125%、150%、200% DPI。构建、扫描烟测和 `git diff --check` 必须通过。
