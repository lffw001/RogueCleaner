# 恢复记录清理与全中文显示设计

## 目标

- 恢复中心可以手动删除当前批次，并可一次清理长期积压的旧批次。
- 删除只作用于“流氓软件克星数据\backups”中的精确批次目录及同批次处理报告，不能越过数据目录。
- 用户界面的按钮、栏目、状态、类型和说明统一使用中文；软件官方名称、文件路径、命令、CLSID 等原始证据保留原文。

## 方案比较与结论

1. 只提供“全部清空”：操作简单，但容易误删仍需回滚的近期记录，不采用。
2. 只提供逐条删除：最安全，但无法解决长期堆积，不采用。
3. 提供“删除当前批次”和“清理旧记录”：兼顾可控删除与日常维护，采用。

“清理旧记录”保留最近 30 天的全部批次，并无条件保留最新 20 个批次；只有同时超过 30 天且不在最新 20 个中的批次才进入清理预览。执行前显示批次数和占用空间，并要求二次确认。

## 数据与安全边界

- 根据清单中的 `CreatedAt` 判断时间；无法解析时回退到批次目录时间，仍无法判断则不自动清理。
- 删除前将路径规范化，必须是备份根目录的直接或间接子目录，且不能等于备份根目录本身。
- 删除批次目录后，再删除名称精确匹配该批次编号的 `cleanup-<编号>.json` 和 `context-menu-<编号>.json`。
- 删除后回读确认目录和报告均不存在；部分失败时保留未删内容并向用户报告。
- 本次测试只创建和删除隔离的模拟批次，不处理用户现有恢复记录。

## 界面与中文显示

- 恢复中心底部操作区依次为“清理旧记录”“删除当前批次”“恢复当前批次”“关闭”。
- 恢复列表和详情中的内部英文状态继续保存在数据层，显示层映射为“已处理、失败、已打开卸载窗口、已跳过”。
- 右键管理对常见英文菜单做确定性翻译，例如：
  - `Open Folder as PyCharm Project` → `作为 PyCharm 项目打开文件夹`
  - `Open Git Bash here` → `在此处打开 Git Bash`
  - `Open Git GUI Here` → `在此处打开 Git 图形界面`
- 用户详情中的 `Shell 命令`、`Shell 扩展` 显示为“右键命令”“右键扩展”；内部判断仍使用原值。
- Windows 打包右键扩展不再只放在高级页；已能解析到实际组件且确认属于第三方软件的项目合并到普通右键管理，并继续通过当前用户的 Windows 右键扩展屏蔽列表启停。
- 主扫描表的表头、文字、勾选框和图标固定居中，单元格格式化和刷新不能把文字列改回左对齐。
- 不翻译软件品牌、路径、命令参数和注册表证据，避免信息失真。

## 验证

- 构造 25 个模拟批次，确认最新 20 个和最近 30 天记录不进入自动清理。
- 验证越界路径被拒绝、目标批次和同编号报告被删除、相邻批次和报告不受影响。
- 验证右键菜单常见英文标题和类型的中文显示映射。
- 验证已安装的 Windows 打包第三方右键扩展可进入普通右键管理；系统快捷菜单名称和分组使用中文显示。
- 运行现有安全冒烟测试；不运行会创建服务和计划任务、可能触发安全软件的完整验收模式。
