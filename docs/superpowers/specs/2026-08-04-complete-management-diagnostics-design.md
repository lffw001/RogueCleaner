# 启动项、右键菜单与流氓组件完整管理诊断设计

## 1. 产品定位

本次将“流氓软件克星”从只显示命中厂商规则的清理器，升级为离线、一次性运行的 Windows 启动项/右键菜单管理与弹窗、守护、流氓组件诊断工具。

程序保持以下边界：

- 单个 WinForms EXE，不安装服务、不常驻、不联网。
- 不做病毒查杀、实时拦截、驱动防护、漏洞修复或云信誉。
- 完整枚举管理范围内的对象，但不把“被扫描到”解释成“有问题”。
- 厂商身份、行为事实、风险建议和允许执行的动作分别计算。
- 所有实际修改继续备份、复核并支持恢复。

## 2. 选定方案

采用分层诊断管线，不继续在每个扫描器里混合厂商关键词、风险评分和清理动作。

处理顺序固定为：

1. `InventoryCollector` 完整采集对象。
2. `IdentityResolver` 判断对象属于谁。
3. `BehaviorAnalyzer` 描述对象做了什么。
4. `RelationshipCorrelator` 将同一软件的多个组件关联起来。
5. `DecisionPolicy` 决定展示层级、建议和动作权限。
6. `Management UI` 分层展示并执行用户明确选择的动作。

即使某层失败，前面已采集的对象仍然保留，并显示“部分信息读取失败”，不得静默丢掉整类结果。

## 3. 完整采集范围

### 3.1 启动与常驻管理

- HKCU/HKLM 的 `Run`、`RunOnce` 及对应 32/64 位视图。
- 当前用户和所有用户启动文件夹。
- 登录、启动、空闲、定时触发的计划任务。
- 自动、延迟自动和触发启动的非 Windows 核心服务。
- 浏览器 Native Messaging Host 和策略强装扩展。
- 当前正在运行且能关联到上述持久化入口的进程。

### 3.2 右键与资源管理器管理

- 文件、文件夹、文件夹空白处、磁盘、桌面、快捷方式及常见文件类型的 `shell` 和 `shellex`。
- CLSID 对应的 InprocServer32、LocalServer32、图标、显示名和命令。
- “此电脑”、导航栏和网络位置入口。
- 文件默认打开程序与“打开方式”列表；默认打开程序只管理和提示，不自动更改。

### 3.3 弹窗/流氓组件诊断

- 隐藏卸载项、子组件、缺少卸载入口和无效卸载入口。
- 当前可见顶层窗口与所属进程，用于确认“当前确实存在弹窗窗口”，不通过名字猜测弹窗。
- 与启动项、服务、任务关联的守护、更新、通知、推荐组件。
- 进程的签名、版本信息、安装归属、父进程和有限的已加载模块信息。
- 当前 TCP 连接与 PID 的关联只作诊断证据，不因联网本身判定异常。

不递归扫描所有文件、不注入进程、不读取用户文档、不抓取网络内容。

## 4. 数据模型

### 4.1 InventoryItem

每个原始对象至少包含：

- 稳定对象 ID、来源类别和原始位置。
- 用户可见名称、命令、目标文件、CLSID、服务名、任务路径等结构化字段。
- 当前状态：启用、禁用、目标缺失、读取失败、需要管理员权限。
- 可执行动作能力：禁用、删除、弹出卸载器、仅报告、不可操作。

采集器不设置厂商、风险或“流氓”标签。

### 4.2 SoftwareIdentity

沿用并强化当前多证据身份模型：

- 有效 Authenticode 签名主体。
- Publisher、CompanyName、ProductName、文件描述。
- MSI ProductCode 查询结果。
- 卸载项和安装目录归属。
- 明确且有边界的产品专属标识。

GUID、哈希、PID、完整注册表路径、随机参数和系统宿主不得识别厂商。冲突身份保持未知。

### 4.3 BehaviorFact

行为只记录可验证事实，例如：

- 登录时启动、服务自动启动、任务定时拉起。
- 添加右键入口、接管默认打开方式、策略强装浏览器扩展。
- 控制面板隐藏、卸载命令缺失、目标文件不存在。
- 当前存在可见窗口、同产品存在多个持久化入口。
- 名称或产品元数据明确标识为广告、推荐、通知、守护组件。

“有网络连接”“有服务”“有数字签名”本身均不是异常事实。

### 4.4 SoftwareGroup

关联优先级依次为：

1. 同一有效签名主体和安装根目录。
2. 同一卸载项/MSI 产品及安装目录。
3. 同一规范化目标文件或 CLSID 服务器文件。
4. 同一明确产品身份和父子目录。

不得只靠名称相似或短关键词合并。关联不确定时保持独立项目，避免把正常主程序和第三方组件合并后一起处理。

## 5. 四层展示与判定政策

### 5.1 建议处理

必须有客观异常证据，典型组合包括：

- 注册表/右键/打开方式指向已不存在的目标文件。
- 已确认的广告、推荐、弹窗子组件，同时存在启动、服务或任务入口。
- 已确认的守护/自动恢复子组件，同时存在两个以上相互印证的持久化入口。
- 浏览器策略强装且并非 Windows/浏览器自身管理项。

这类项目仍默认不勾选；“勾选可清理”只选择其中动作可恢复、目标明确且无身份冲突的项目。

### 5.2 可管理

正常第三方启动项、服务、任务、右键菜单、资源管理器入口和打开方式。它们不是风险项，只说明“可以关闭/移除以及可能影响什么”。由用户手动选择，永不自动勾选。

### 5.3 系统/可信

Windows 核心组件、微软系统任务、系统服务以及身份明确且无异常行为的受信组件。默认折叠，不参与批量处理。高级查看中可读证据，但关键系统对象不可操作。

有效第三方签名只确认归属，不自动进入“系统/可信”；普通已签名第三方组件仍属于“可管理”。

### 5.4 未知

身份不足、证据冲突或读取不完整的对象。仍完整显示位置和行为事实，但不提供自动建议；存在独立异常行为时仅允许“只提示”或用户逐项执行可恢复的管理动作。

### 5.5 风险与动作分离

展示层级、风险级别和动作权限是三个字段：

- 展示层级：建议处理、可管理、系统/可信、未知。
- 风险级别：高、中、低、信息。
- 动作权限：建议可恢复处理、仅手动管理、仅报告、禁止操作。

任何一个评分不得直接推导另两个字段。

## 6. 处置策略

- 启动项优先“禁用并保存原值”，恢复时写回原位置和数据。
- 普通 `shell` 右键项优先使用可逆禁用标志；不支持标准禁用的 `shellex` 才在完整导出后删除注册项。
- 服务和计划任务只禁用，不删除。
- 默认打开程序不自动修改。
- 有原厂卸载器的明确子组件只弹出卸载器，不代替用户点击卸载。
- 未知、身份冲突、关键系统对象、目标范围不清的项目禁止批量处理。
- 清理前显示将影响的关联组件，清理后逐项回读并重新扫描。

## 7. 界面设计

顶部保留现有扫描、清理、恢复、报告和更新入口，并继续使用可换行布局避免高 DPI 遮挡。

结果区增加：

- 一级页签：总览、启动项、右键菜单、弹窗/流氓诊断。
- 分层筛选：建议处理、可管理、系统/可信、未知。
- 状态筛选：启用、已禁用、目标缺失、读取失败。
- 软件分组视图：展开后显示该软件关联的启动项、服务、任务、右键、窗口和卸载项。
- 证据详情：分别展示“身份依据”“行为事实”“建议原因”“处理影响”，不再只有一段混合 Evidence。

默认视图只展开“建议处理”，其余层级显示数量但不制造警报感。搜索覆盖名称、厂商、产品、位置和行为事实。

## 8. 错误处理与性能

- 每个采集器返回结果、错误和耗时；一个采集器失败不能使其他类别消失。
- 非法路径、拒绝访问、损坏注册表值、无签名和 WMI/COM 查询失败均转成局部状态。
- 身份文件、签名、MSI、卸载项和安装目录归属按规范化键缓存。
- 进程模块和网络连接只针对已关联或候选进程补充，避免全系统深度分析拖慢扫描。
- 在当前测试机器上，冷扫描目标不超过 8 秒，重复扫描目标不超过 5 秒；超时的诊断增强项可降级但必须明确显示。

## 9. 代码边界

仍编译为一个 EXE，但不继续把全部逻辑堆在单个 C# 文件中。按职责逐步拆分：

- `Models.cs`：采集对象、身份、行为、软件组和决策结果。
- `InventoryCollectors.cs`：启动项、右键、服务、任务、浏览器和文件关联采集。
- `IdentityResolver.cs`：文件、签名、MSI 和安装归属。
- `BehaviorAnalyzer.cs`：客观行为事实。
- `RelationshipCorrelator.cs`：软件组件关联。
- `DecisionPolicy.cs`：四层展示和动作权限真值表。
- `CleanerEngine.cs`：备份、应用、复核、恢复。
- 现有主文件保留程序入口、兼容迁移和 WinForms UI，随后再按风险逐步收敛。

拆分只改变源码组织，不增加运行时文件或第三方依赖。

## 10. GitHub 反馈闭环

### 10.1 用户入口

每个扫描结果提供“反馈判断问题”入口，反馈类型包括：

- 误报：正常项目被标为建议处理或风险过高。
- 漏报：明确存在的启动项、右键项或弹窗组件没有显示。
- 身份错误：项目存在，但厂商或产品归属错误。
- 关联错误：不同软件被错误分组，或同一软件组件未关联。

点击后先显示本地预览窗口，用户可以补充说明，并明确看到即将公开提交的内容。程序在用户确认后生成脱敏 Markdown/JSON 报告，将简短摘要复制到剪贴板，并打开仓库的 GitHub Issue Form；最终提交动作由用户在浏览器登录 GitHub 后完成。

程序不内置仓库 Token，不要求用户输入 Personal Access Token，不在后台直接创建 Issue。

### 10.2 脱敏规则

允许包含：

- 软件版本、Windows 版本和系统架构。
- 结果类别、展示层级、风险、动作权限和对象类型。
- 文件名、有效签名主体、CompanyName、ProductName、Publisher。
- 规范化后的行为事实和身份依据。
- 可选的文件 SHA256；默认关闭，由用户主动勾选。

必须删除或替换：

- 用户名、SID、计算机名、用户名目录和临时目录绝对路径。
- 命令行中的文档路径、URL、账号、令牌和用户参数。
- 完整注册表数据中可能含有的用户内容。
- 网络连接的本地/远端地址和端口。
- 与当前反馈对象无关的软件、进程和扫描结果。

报告只包含用户点选的对象及其必要关联组件，不上传完整系统清单。提交前允许逐字段取消包含。

### 10.3 GitHub 结构

仓库增加 `.github/ISSUE_TEMPLATE/recognition-feedback.yml`，使用结构化字段收集反馈类型、软件版本、当前判断、用户预期和脱敏证据。模板自动使用识别反馈标签；维护阶段再区分误报、漏报、身份错误和关联错误。

预填 URL 只携带短标题和少量字段，避免 URL 过长；详细脱敏内容复制到剪贴板，由用户在表单中确认后粘贴。若浏览器或 GitHub 不可用，本地反馈文件仍保留，程序提供“打开反馈文件夹”和“复制反馈内容”。

### 10.4 反馈生效边界

正式程序不得在扫描时读取公开 Issue 并把内容直接转成厂商规则、白名单或清理动作。GitHub Issue 是不可信用户输入，只能作为待验证样本。

后续开发维护流程可以按标签读取 Issue，并依次执行：

1. 去重并检查脱敏内容是否足够。
2. 复核身份证据、行为事实和用户预期。
3. 将问题转成可重复的正向或负向回归用例。
4. 修正规则、解析器、关联器或决策真值表。
5. 运行完整碰撞、扫描、清理和恢复验收。
6. 在 Issue 中注明修复版本并关闭。

只有通过测试并随正式签名/校验的 EXE 发布的修改才会影响用户扫描结果。该闭环不等同于云端规则库，也不改变程序离线工作的产品边界。

## 11. 实施阶段

1. 建立新模型和决策真值表，让现有采集结果先经过统一决策层。
2. 将启动项和右键扫描改为完整枚举，实现四层展示及禁用/恢复。
3. 增加软件对象关联、隐藏卸载项、可见窗口、相关进程和网络诊断。
4. 改造 UI 分组、筛选和证据详情。
5. 增加反馈预览、逐字段脱敏、本地回退和 GitHub Issue Form 模板。
6. 扩充验收器，完成真实系统对照、反馈脱敏、性能和高 DPI 验证。

每阶段均需保持可编译、可扫描、可恢复，不以最后一次大合并作为唯一验证点。

## 12. 验收标准

- 启动项和右键菜单的完整枚举结果能与对应注册表、启动文件夹、任务和服务读回数量对照。
- 正常第三方项目显示为“可管理”，不显示为高风险或建议清理。
- Corel GUID、Thunderbird、短词、随机路径、系统宿主等负向样本全部不误认厂商。
- 明确异常但身份未知的项目显示“未知/仅提示”，不可进入批量清理。
- 同一软件的启动项、服务、任务、右键和卸载项能在证据充分时正确分组；不同软件不得因短词合并。
- 目标缺失的残留能进入“建议处理”，备份、清理、复扫和恢复全链通过。
- 服务/计划任务仅禁用，默认打开程序不自动修改，系统/可信项不可批量处理。
- 单项采集异常不会令整类结果静默消失，报告记录失败阶段。
- `--identity-smoke`、完整扫描烟测、验证版验收、真实本机扫描和 125%/150%/200% DPI 布局验证通过。
- 正式版仍为单 EXE、离线、不常驻，不引入杀毒或实时防护能力。
- 反馈预览不会泄露用户名、SID、计算机名、用户目录、命令行私密参数或网络地址。
- 未登录 GitHub、浏览器打开失败和用户取消提交时，本地报告仍可复制和查看。
- GitHub Issue 内容无法在未经代码审核和回归测试的情况下改变本地识别或清理结果。

## 13. 明确不做

- 云端规则库和云端判定。
- 病毒特征、文件查杀、内存查杀和隔离区。
- 内核驱动、实时注册表/文件/进程拦截。
- 网络内容审查、抓包和 URL 信誉判定。
- 自动删除未知项目或自动卸载正常主程序。
- 在 EXE 中保存 GitHub Token，或将公开 Issue 自动执行为本地规则。
