本轮 `--ui-smoke` 增加的 100%、125%、150%、200% 检查是进程内的**几何模拟**：它按目标比例重排控件、检查边界并保存截图。这能尽早发现固定像素、换行和容器裁切问题，但不能证明 Windows 在真实缩放、实际 `DeviceDpi`、任务栏工作区、字体回退和多显示器切换下的行为。

几何模拟通过是常规发布的必要条件，不是充分条件；只要下方真实验收矩阵有任一项缺少截图、日志或人工检查结果，就不得宣称“真实高缩放已验证”或关闭 #3。

## 两类证据的边界

| 证据 | 能证明什么 | 不能证明什么 |
|---|---|---|
| `--ui-smoke` 几何模拟截图与边界断言 | 目标逻辑尺寸下主要控件没有负坐标、重叠或父容器裁切；布局分支会被执行 | 当前 Windows 的实际 DPI、非客户区尺寸、字体度量、任务栏工作区、拖动到另一块屏幕后的重新缩放 |
| Windows 真实缩放验收 | 该显示器/缩放组合下的实际渲染、可点击性、扫描过程与工作区约束 | 未覆盖的分辨率、显卡驱动、字体或多显示器组合 |

报告中必须写明“几何模拟”或“真实 Windows DPI”，不得把前者简称为“已验证 200% DPI”。

## 真实 Windows DPI 验收矩阵

在至少一台 1920 × 1080 和一台 2560 × 1440（2K）显示环境中，分别切换 Windows 显示缩放为 100%、125%、150%、200%。每一个格子均要重新启动程序，并记录显示分辨率、实际工作区、Windows 缩放值、程序版本和截图路径；如使用同一块显示器完成多个档位，也要逐档记录。

| 缩放 | 主界面必须覆盖的状态 | 关键对话框必须覆盖 | 必须保留的证据 |
|---|---|---|---|
| 100% | 默认窗口；最小窗口；扫描进行中；扫描完成且有结果；窄窗口下的统计卡、右侧详情与页脚 | 反馈；右键管理；专用右键；高级兼容；右键编辑；IE 菜单编辑；恢复中心；关于 | 每个主界面状态截图、每类对话框截图、`--ui-smoke` 报告和人工检查记录 |
| 125% | 同上 | 同上 | 同上 |
| 150% | 同上 | 同上 | 同上 |
| 200% | 同上；特别检查标题区、六个主操作、统计卡两行布局、扫描进度与详情分栏 | 同上；特别检查反馈选项换行、右键管理工具栏和编辑窗体底部操作区 | 同上，并记录有效工作区是否仍满足最小窗口要求 |

### 每张验收截图的判定标准

- 产品标题、版本、导航、主操作按钮及其文字完整可见；没有被窗体、父容器或同级控件遮挡。
- “开始扫描”“清理勾选”“勾选可清理”“只勾低”“恢复中”“证据报”等主操作均能鼠标点击；主操作栏不依赖横向滚动才能访问按钮。
- 扫描进行中出现进度条后，按钮、搜索/筛选区和结果区不得被挤出或覆盖；扫描完成后不能残留错误的滚动偏移或不可点击区域。
- 统计卡、列表表头、右侧详情卡和页脚文字不被截断；数据表自身的横向滚动用于数据列是允许的，但不能用来补救工具栏或对话框操作按钮。
- 对话框的单选项、列表、输入区和确认/关闭操作完整可用；没有文字裁切、控件重叠、底部按钮越界或仅通过滚动才能完成基本操作的情况。
- 每个档位至少人工完成一次：打开反馈窗体、打开右键管理及其专用/高级入口、进入恢复中心、启动一次只读扫描并等待完成。

## 发布判定与留档

1. 先运行 `--ui-smoke`。非零退出码、缺少目标档位截图或任何边界断言失败，直接阻止发布。
2. 再完成上表所有真实 Windows DPI 组合。每格保留截图，并在验收记录中写明“通过/失败/不适用”及原因；“未测”不能写成通过。
3. 如发现遮挡、点击失败或显示不全，修复后必须重跑受影响档位，并复跑全部四档的主界面状态；不能仅凭一张默认窗口图关闭 #3。
4. 只有几何模拟与真实矩阵均通过，且构建、现有功能烟测和 `git diff --check` 通过，才可由作者决定把 #3 标为已验证、公开回复或关闭。v2.0.15 的反馈发布不改变这一条件。

## PerMonitorV2 边界

本轮**不切换到 PerMonitorV2**。当前交付约束是单 EXE；对 .NET Framework WinForms 而言，Microsoft 的 [高 DPI WinForms 配置说明](https://learn.microsoft.com/en-us/dotnet/desktop/winforms/high-dpi-support-in-windows-forms)将 PerMonitorV2 设定放在与可执行文件配套的应用配置中，而不是只改一个 manifest 标记。贸然加入旁路配置文件会改变单文件交付边界，也没有经过双显示器/不同 DPI 之间拖动窗口的验收。

若未来决定改变交付边界，需单独设计并验证：配置文件随包交付、缺失/损坏时的降级行为、100% ↔ 200% 双显示器拖动、对话框重建和回归矩阵。该设计与本轮布局修复分开，不能以“开启 PerMonitorV2”替代真实验收。
