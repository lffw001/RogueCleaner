# 右键管理与流氓诊断统一发现设计

## 问题

右键管理使用完整枚举器，覆盖常见右键根、文件类型专属菜单和 Windows 11 现代右键扩展；开始扫描仍使用固定传统根，并跳过已经屏蔽的 CLSID。结果是同一个插件可能在右键管理中存在，却不进入诊断；用户手动禁用后也会从诊断证据中消失。

## 决策

1. 右键管理和流氓诊断必须复用同一套只读发现数据。
2. 右键管理展示全部第三方可管理项目，不评价风险。
3. 流氓诊断只桥接能确认厂商、组件文件或异常行为的第三方插件。
4. 已启用的可疑插件进入精确禁用动作；传统 Shell 扩展写入 Windows `Blocked`，传统命令使用对应可逆显隐机制，现代右键扩展只屏蔽当前 CLSID。
5. 已禁用的可疑插件仍显示为“已治理”，不可再次清理，不计入建议处理数量。
6. 软件更新或重装后若重新注册或重新启用插件，下次扫描必须重新进入可治理结果；不在后台常驻、不在扫描阶段自动修改系统。
7. 同一个 CLSID 在多个右键位置只形成一个治理动作，但保留发现位置摘要；32/64 位和当前用户/所有用户的实际状态分别验证。

## 识别边界

- 搜狗、WPS、百度网盘、360 等仅作为回归样本，规则必须适用于所有厂商。
- 仅凭出现在右键管理中不能判为流氓；必须有可验证的第三方身份，以及额外右键注入、广告、推广、云文档上传、扫描或软件管家等治理语义。
- Microsoft 系统组件、身份冲突和来源未知项目不进入批量清理；必要时仅提示。
- 已禁用状态是治理证据，不等于注册项不存在。

## 验证

- 纯规则回归覆盖启用、已禁用、重新启用、传统 Shell、文件类型专属和现代右键。
- 当前机器只读验证搜狗已屏蔽扩展仍显示“已治理”，WPS 已注册扩展进入诊断，百度网盘现代/专属入口若存在也进入同一桥接链。
- 身份、扫描和 UI 烟测必须为零失败；扫描不创建服务、任务或测试注册项。
