# 右键发现与诊断一致性规范

本规范适用于右键管理、开始扫描、弹窗/流氓诊断、清理勾选、恢复中心，以及以后新增的所有右键类型。

## 单一发现源

- 右键管理和风险诊断必须调用同一个只读发现服务，禁止分别维护两套注册表根、文件类型或现代菜单枚举逻辑。
- 发现服务统一覆盖传统 Shell 命令、Shell 扩展、拖放处理器、文件类型专属菜单和 Windows 11 现代右键扩展。
- 新增任何右键类型时，必须同时接入管理视角和诊断桥接器；只在一个页面可见视为回归缺陷。

## 两种视角

- 右键管理展示全部可识别第三方项目，供用户主动启用、禁用或查看，不因“存在”自动判为风险。
- 流氓诊断只显示厂商或组件身份已确认、且确实形成额外右键注入的项目；系统组件、身份冲突和未知来源不得进入批量清理。
- 启用中的可疑插件提供精确、可恢复的禁用动作，不卸载所属主程序。
- 已禁用的可疑插件仍显示为“已治理”，不可再次勾选，不能因为位于屏蔽列表而从扫描证据中消失。

## 更新与重装

- Windows `Shell Extensions\Blocked`、`LegacyDisable` 等当前状态必须由发现服务读取并展示。
- 软件更新或重装后，若同一插件、替换 CLSID 或新注册位置重新启用，下次扫描必须重新进入可治理结果。
- 扫描阶段只读，不得自动改注册表；项目不为此增加后台服务、常驻监控或静默治理，避免安全软件拦截和用户无感修改。

## 回归要求

- 至少覆盖一个启用传统扩展、一个已禁用扩展、一个文件类型专属菜单和一个现代右键扩展。
- 搜狗、WPS、百度网盘、360 仅作为实机或纯规则样本，禁止为单一厂商建立旁路逻辑。
- 回归必须验证：管理发现数不少于诊断候选源；已禁用项目状态为“已治理”；重新启用后恢复为可处理；身份未知项目不进入清理。
- 正式构建前执行身份、只读扫描和 UI 烟测，不使用会创建服务或计划任务的验收测试。
