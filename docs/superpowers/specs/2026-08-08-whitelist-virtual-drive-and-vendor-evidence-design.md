# 白名单、虚拟盘只读诊断与厂商复核材料设计

## 目标

在不降低现有扫描证据完整性、不引入云端规则、也不自动删除网盘组件的前提下，落实 Issue #1、#5 和 #7 中可立即交付的部分。

## 方案选择

1. 将白名单做成只按厂商名匹配：实现简单，但同厂商不同组件会被一并隐藏，风险过高。
2. 将白名单做成可编辑的技术位置规则：过于复杂，普通用户难以理解且容易误填。
3. 采用扫描项目的稳定目标标识加用户可见名称作为本地白名单记录：推荐。用户只能从已有结果主动加入；扫描仍采集证据，只在结果层标为“已白名单”，不自动处理。

虚拟盘采用只读盘符、驱动器类型、卷标、文件系统和关联厂商证据诊断；不写注册表、不卸载、不删除驱动或设备。火绒复核材料仅输出当前 EXE 的版本、SHA-256、签名主体和生成时间。

## 数据与交互

- 数据文件为数据目录 `state/user-whitelist.json`，由程序自行创建，包含格式版本和白名单条目；条目以 `ActionTarget` 派生稳定键与项目名称组成。
- 主窗口工具栏增加“白名单”入口；可查看、移除已保存条目。结果右键/操作入口只允许把当前扫描项目加入白名单。
- 白名单命中项保留在结果表、显示低风险与“已白名单”状态，禁止勾选和批量清理；详情仍显示原始证据，避免把忽略误认为不存在。
- 扫描结束后追加“网盘虚拟盘（只读诊断）”结果；只有盘符存在、类型属于网络盘或可移动/固定盘且名称、卷标或关联路径出现明确网盘标识时才展示。所有结果为 `ReportOnly`。
- “证据报告”同时可包含虚拟盘的只读证据；火绒材料独立保存到 `reports/vendor-review-*.md`，不自动发送。

## 安全边界与验收

- 不读取 GitHub Issue 作为规则输入；#4 的 JSON 规则仓库建议不进入本轮，外部数据也不拥有清理权限。
- 不自动对白名单中的项目进行注册表、服务、计划任务、文件或驱动操作。
- 不修改任何虚拟盘、设备、盘符或网盘客户端。
- 回归覆盖白名单键稳定性、白名单命中不可选、虚拟盘结果只读、厂商材料 SHA-256 可复算；并运行既有扫描、UI 与反馈烟测。
