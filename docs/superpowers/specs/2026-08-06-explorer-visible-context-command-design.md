# 资源管理器实际右键命令显示设计

## 目标

右键管理列表优先显示用户在 Windows 资源管理器中真正看到的命令文字，例如“打开”“选择左边文件进行比较”，不再以“某软件右键菜单”代替具体功能。

## 统一识别链

1. 普通 `shell` 命令读取 `MUIVerb`、默认值和间接资源字符串，得到资源管理器显示文字。
2. `ExplorerCommandHandler`、传统 `ContextMenuHandlers` 和应用包清单声明的动态扩展按 CLSID 识别，不为 Beyond Compare 或任何厂商写专用扫描入口。
3. Windows 11 应用包同时读取 `windows.fileExplorerContextMenus` 与 `windows.fileExplorerClassicContextMenuHandler`；相同 CLSID、相同出现位置只保留一项。
4. 动态命令通过独立的隐藏子进程加载处理器，并用与出现位置匹配的文件、文件夹或磁盘样本调用 `IExplorerCommand.GetTitle`；存在子命令时优先显示实际子命令文字。
5. 探测设置严格超时并按 CLSID、出现位置缓存。超时、崩溃或接口不支持时，主程序继续枚举，名称降级为“软件名 + 动态右键命令（文字未读取）”。

## 安全与性能

- 不在界面线程或扫描主进程中加载第三方 Shell DLL。
- 不执行右键命令，不修改文件，不触发清理，只读取标题和图标资源。
- 系统包不做动态探测，仍按现有规则隐藏，减少无意义开销。
- 单个处理器失败不能终止整次右键枚举。

## 界面

- “右键里显示的名称”列展示实际命令文字。
- 图标优先采用动态命令返回的图标，其次采用组件文件图标，最后使用统一占位图标。
- 详情保留 CLSID、包名、组件路径和探测失败原因，便于判断；技术信息不替代主列表的人话标题。

## 验证

- 静态回归覆盖“打开”等常见命令。
- 应用包解析回归覆盖现代与传统打包声明、场景归一化和去重。
- 在安装 Beyond Compare 5 的本机只读验证中，确认至少一个场景能显示它返回的实际命令文字；失败时必须显示明确兜底名且枚举不阻塞。
- 构建后运行身份、扫描和界面冒烟测试，不运行会创建服务或计划任务的验收测试。
