# 作者与外部主页入口拆分设计

## 目标

解决主界面底部“作者：aakk007”一次点击可能打开多个、数量不稳定的浏览器标签页问题。作者署名与两个外部主页入口彻底分离，使每个可点击控件只负责一个网址。

## 最终界面

主界面底部状态栏右侧按从左到右排列：

1. `作者：aakk007`：普通灰色文字，不显示下划线、手型光标或点击反馈，也不绑定任何跳转事件。
2. 吾爱破解入口：使用吾爱破解官网 `favicon.ico` 的官方红色图标，旁边显示蓝色文字 `吾爱破解`。
3. GitHub 入口：使用 GitHub 官网 `favicon.ico` 的官方图标，旁边显示蓝色文字 `GitHub`。

两个入口之间保留适当间距或细分隔线，与现有浅灰蓝状态栏和安全工具风格一致。在最小窗口及高 DPI 环境下不得重叠、截断或挤出窗体。

## 资源策略

- 官方图标来源固定为 `https://www.52pojie.cn/favicon.ico` 和 `https://github.com/favicon.ico`。
- 下载后的 ICO 文件纳入项目源码资源，并在构建时嵌入 EXE。
- 正式程序运行时从程序集资源读取图标，不联网下载，不依赖 EXE 外部图片文件。
- 继续保持正式发布物为单文件 EXE。

## 交互行为

- 点击吾爱破解图标或文字，只打开 `https://www.52pojie.cn/home.php?mod=space&uid=286924`。
- 点击 GitHub 图标或文字，只打开 `https://github.com/aakk007`。
- 点击作者署名不执行任何操作。
- 两个外部入口分别增加短时间防连点保护；同一入口在保护窗口内重复触发只执行一次。
- 吾爱和 GitHub 是两个独立入口，点击其中一个不得触发另一个。
- 鼠标悬停分别显示 `打开作者的吾爱破解主页` 和 `打开作者的 GitHub 主页`。

## 代码边界

- 删除原 `authorLink` 的双网址跳转职责以及 `OpenAuthorLinks()` 一次启动两个进程的实现。
- 将作者控件改为普通 `Label`。
- 为两个外部入口建立独立控件和独立事件处理。
- 浏览器启动收敛到一个接收单一 URL 的辅助方法；每次调用最多启动一个网址。
- 资源读取失败时保持文字入口可用，图标区域使用空白或安全占位，不因图标异常导致主窗体启动失败。

## 验证标准

1. 静态检查确认作者署名没有 Click 或 LinkClicked 事件。
2. 单击吾爱入口一次，只收到一个吾爱 URL 启动请求，没有 GitHub 请求。
3. 单击 GitHub 入口一次，只收到一个 GitHub URL 启动请求，没有吾爱请求。
4. 快速连续触发同一入口时，防连点窗口内只收到一次启动请求。
5. 两个入口依次点击时，各自仍能正常打开一次，不互相屏蔽。
6. `--ui-smoke` 覆盖默认尺寸、最小尺寸和高 DPI 布局，作者文字及两个入口均完整可见且不重叠。
7. 正式构建通过，生成的 EXE 内含两枚图标资源，运行目录不新增图标文件。
8. 正式版常规烟测通过，发布包仍保持单 EXE 结构。

## 不在本次范围

- 不修改作者名称、吾爱 UID、GitHub 用户名或其它页面链接。
- 不改动主界面其它按钮和扫描、清理、恢复、反馈逻辑。
- 不新增运行时联网加载图片、浏览器选择菜单或第三方图标库。
